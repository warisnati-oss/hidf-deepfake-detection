คอมพิวเตอร์จับ deepfake ที่คนดูไม่ออกได้ไหม?

หน้านี้สรุปงานของโปรเจกต์ทั้งหมด พร้อมคำศัพท์และเหตุผลของแต่ละขั้น เราใช้ dataset ชื่อ HiDF (ปี 2025) ซึ่งเป็นรูป face swap ที่คนตรวจแยกไม่ออกว่าจริงหรือปลอม เราสร้างโมเดลหลายแบบที่ดูรูปแล้วตอบว่า "real" หรือ "fake" แล้วตรวจอย่างละเอียดว่าผลลัพธ์เชื่อถือได้จริง ตอนนี้ Phase 1–5 เสร็จแล้ว เหลือทำสไลด์ (Phase 6)

คำศัพท์ความคืบหน้า + เกณฑ์Literature reviewข้อมูลPreprocessingFeature ที่ออกแบบเอง โมเดลผลลัพธ์Robustnessโมเดลดูตรงไหน Fairnessตรวจ leakageข้อจำกัดไฟล์

สรุปสั้น ๆ

โมเดลที่ดีที่สุด99.8 %

M3 (DINOv3 + LoRA) ตอบถูก 99.76 % จากรูป test 9,600 รูปที่ไม่เคยเห็นมาก่อน ในรูปจริง 5,366 รูป ทายผิดว่าเป็น fake แค่ 2 รูป

Deep learning ชนะในรูปที่เสียหาย0.55

โมเดล classical (feature ที่ออกแบบเอง) แม่น 98 % กับรูปปกติ แต่พอเบลอนิดเดียว AUC เหลือแค่ระดับเดาสุ่ม ส่วน M3 ยังแม่น ≥ 98.6 % ในทุกแบบที่ทำให้รูปเสียหาย

คำศัพท์ (อ่านก่อน)

ความหมายของคำที่ใช้ในหน้านี้ · กดเพื่อเปิด/ปิด
Model / classifier
โปรแกรมที่เรียนรู้กฎจากตัวอย่างแทนที่จะมีคนเขียนกฎให้ โมเดลของเรารับรูปแล้วให้ score ตั้งแต่ 0 (real) ถึง 1 (fake)
Label
คำตอบที่ถูกต้องของแต่ละรูป ("real" หรือ "fake") โมเดลเห็น label เฉพาะตอน train เท่านั้น
Train / validation / test split
แบ่งข้อมูลเป็นสามกอง Train (72 %) ให้โมเดลเรียน Validation (14 %) ใช้ตัดสินใจ เช่น จะหยุด train เมื่อไหร่ Test (14 %) ใช้ครั้งเดียวตอนท้าย เหมือนข้อสอบไฟนอลที่โมเดลไม่เคยเห็น
Threshold
ค่า score ที่ถ้าเกินแล้วเราจะตอบว่า "fake" เลือกจาก validation เท่านั้น ห้ามเลือกจาก test
Accuracy
สัดส่วนรูป test ที่ตอบถูก
AUC
วัดว่า score เรียง fake ไว้สูงกว่า real ได้ดีแค่ไหน โดยดูทุก threshold พร้อมกัน 1.0 = สมบูรณ์แบบ 0.5 = เดาสุ่ม มีประโยชน์เพราะไม่ขึ้นกับ threshold ตัวใดตัวหนึ่ง
False positive / false negative
False positive คือรูปจริงที่ถูกทายว่า fake (แจ้งเตือนผิด) False negative คือรูป fake ที่หลุดรอดไป ตาราง 2 × 2 ที่นับทั้งสองแบบเรียกว่า confusion matrix
Feature (แนว classical)
ตัวเลขที่เราออกแบบเองด้วยเครื่องมือ image processing เช่น texture, noise, ความถี่ของภาพ แล้วให้โมเดลง่าย ๆ เรียนว่าตัวเลขไหนสำคัญ
Deep learning / neural network
โมเดลที่มีตัวเลขปรับได้ (weights) หลายล้านตัว และเรียน feature เองจาก pixel โดยตรง
Pretrained backbone
network ขนาดใหญ่ที่คนอื่น train ไว้แล้วด้วยรูปหลายล้านรูป (ในงานนี้คือ DINOv3 ของ Meta) เรายืม "ความรู้เรื่องภาพ" ของมันมาปรับใช้กับ deepfake
Fine-tuning, LoRA
Fine-tuning คือ train ต่อด้วยข้อมูลของเรา LoRA คือ train เฉพาะชิ้นส่วนเล็ก ๆ ที่เพิ่มเข้าไป แทนที่จะ train ทั้ง network ถูกกว่าและ overfit ยากกว่า
Zero-shot
ใช้โมเดลโดยไม่ train กับข้อมูลเราเลย แค่ถามมันตรง ๆ
Augmentation
สุ่มเบลอ บีบอัด crop หรือกลับด้านรูปตอน train เพื่อให้โมเดลรับมือกับรูปคุณภาพไม่ดีได้
Overfitting
โมเดลจำตัวอย่างใน train แทนที่จะเรียนกฎทั่วไป ผลคือทำได้แย่กับรูปใหม่
Leakage
โมเดลได้คำตอบผ่าน "ทางลัด" เช่น รูปเดียวกันอยู่ทั้งใน train และ test หรือดูจากชนิดไฟล์ ทำให้คะแนนดูดีกว่าความสามารถจริง
Confidence interval (CI)
ช่วงที่บอกว่าคะแนนอาจเปลี่ยนได้แค่ไหนถ้าใช้ test set ชุดอื่น ถ้าช่วงของสองโมเดลซ้อนกัน แปลว่ายังสรุปไม่ได้ว่าตัวไหนดีกว่า
Grad-CAM
heat map ที่บอกว่าส่วนไหนของรูปทำให้โมเดลตอบแบบนั้น
Epoch
การให้โมเดลดูข้อมูล train ครบหนึ่งรอบ
GPU
ชิปกราฟิกที่ทำให้ train เร็วขึ้น ในงานนี้ train หนึ่งรอบเต็มใช้เวลาประมาณ 3–12 ชั่วโมง

1 · Dataset

HiDF: A Human-Indistinguishable Deepfake Dataset

Kang et al., KDD 2025
ทำอะไร
สร้าง dataset รูป face swap คุณภาพสูง (~62K รูป + 8K วิดีโอ) ที่ผ่านการทดสอบกับคนจริงว่าแยกไม่ออก โมเดลเดิม ๆ ได้ AUC แค่ ~0.70
จุดแข็ง
fake สมจริงกว่า dataset เก่า (FF++, Celeb-DF) ซึ่งคนดูออกง่าย
ข้อจำกัด
โมเดลที่ทดสอบไม่ได้ train บน HiDF เอง ไฟล์ real กับ fake บันทึกต่างกัน (ขนาดไฟล์อย่างเดียวได้ AUC 0.99) และคนเดิมซ้ำหลายรูป ถ้าแบ่งแบบสุ่มจะรั่ว
เราใช้อย่างไร
เป็น dataset หลัก แก้ทางลัดด้วย P1 และ split ตามตัวคน
2 · การประเมินผล + M1

FaceForensics++

Rössler et al., ICCV 2019
ทำอะไร
benchmark วิดีโอ 1,000 คลิป ปลอมด้วย 4 วิธี และ 3 ระดับการบีบอัด เทียบ feature ที่ออกแบบเองกับ CNN
จุดแข็ง
แสดงว่า CNN ชนะ feature ที่ออกแบบเองและชนะคน และการ train ที่บริเวณหน้าดีกว่ารูปเต็ม
ข้อจำกัด
fake รุ่นเก่า คนดูออกง่าย และทุกโมเดลแย่ลงมากเมื่อบีบอัดแรง
เราใช้อย่างไร
ทดสอบทุกโมเดลกับรูปเสียหาย 9 แบบ, adjustment แบบ face crop, และแนวทาง CNN ของ M1
3 · Classical

Unmasking DeepFakes with simple Features

Durall et al., 2020
ทำอะไร
แปลงรูปด้วย FFT เฉลี่ยเป็น spectrum 1 มิติ แล้วใช้ classifier ง่าย ๆ ได้ 100 % บนหน้า high-res โดยใช้ตัวอย่าง train แค่ 20 รูป
จุดแข็ง
ง่าย เร็ว ใช้ข้อมูลน้อย อธิบายได้
ข้อจำกัด
เบาะแสความถี่สูงหายไปเมื่อรูปถูกบีบอัด เบลอ หรือย่อ
เราใช้อย่างไร
เป็นฐานของโมเดล classical (P4) เราเพิ่ม noise, LBP, สี, รอยต่อ รวม 247 feature ได้ AUC 0.998 แต่เบลอ σ2 แล้วเหลือ 0.55 ตรงกับข้อจำกัดนี้
4 · M2

GenD: Deepfake Detection that Generalizes Across Benchmarks

Yermakov et al., WACV 2026
ทำอะไร
ใช้ foundation model (CLIP, DINOv2/v3) แล้ว train แค่ LayerNorm + linear head (~0.03 % ของ weights) พร้อม loss ที่จัดรูป feature บนทรงกลม
จุดแข็ง
ถูกมาก และได้ AUROC ข้าม dataset เฉลี่ยดีที่สุดใน 14 datasets
ข้อจำกัด
ความทนต่อรูปเสียหายขึ้นกับ augmentation เกือบทั้งหมด (ของเรา: ปิด augmentation แล้ว JPEG q30 ตกจาก 96.6 % เป็น 80.5 %)
เราใช้อย่างไร
เป็น M2 บน DINOv3 ได้ AUC 0.9998 โดย train แค่ 101K weights
5 · M3

Robust Deepfake Detection, NTIRE 2026 Challenge Report (DINO-MAC)

Hopf et al., 2026
ทำอะไร
รายงานการแข่งขันตรวจ deepfake ในรูปที่เสียหาย ผู้ชนะ (DINO-MAC) ใช้ DINOv3-L + LoRA, head ที่รวมหลาย token และ train ด้วยขนาดรูปสุ่ม
จุดแข็ง
ทนต่อ noise, blur, การบีบอัดดีที่สุดในการแข่งขัน
ข้อจำกัด
ใช้ทรัพยากรมาก paper train ที่ 384–1152 px เราต้องลดเหลือ 224–320 px และยังช้าที่สุด (~139 นาทีต่อ epoch)
เราใช้อย่างไร
เป็น M3 ทนทานที่สุดในโมเดลเรา (face crop: AUC ≥ 0.997 ในทุกความเสียหาย)
Gap

ช่องว่างที่งานเราเติม

  1. HiDF ถูกอ้างว่ายาก แต่ยังไม่มีใคร train บนมันโดยคุมทางลัด เราเจอและแก้ 2 ทางลัด (การบีบอัด, คนซ้ำ) หลังแก้แล้วทุกโมเดลที่ train ได้ AUC ≥ 0.998 แปลว่า "คนแยกไม่ออก" แต่เครื่องแยกออก
  2. ความต่างจริงระหว่างวิธีคือ robustness (ตาม [2], [5]) รูปปกติ classical ≈ DL แต่รูปเสียหาย classical พัง DL ยังดี ถ้า train ด้วย augmentation
  3. วิธี foundation model ใหม่ [4], [5] ยังไม่เคยทดสอบบน HiDF เราเทียบกับ CNN (M1) ภายใต้เงื่อนไขเดียวกันทั้งหมด

Dataset + Preparation (Train / Val / Test)

ครบ
วิชาต้องการ

ใช้ public dataset และ visualise ทุกด้าน: ภาพรวม (จำนวน class, label, ขนาด, แหล่งที่มา, การแบ่ง train/val/test), รูปตัวอย่าง input/output, กราฟหรือสถิติการกระจายของ class

เราทำอย่างไร
  • HiDF (public, KDD 2025) 2 class: real / fake, 69,476 รูปหลังทำความสะอาด, 1024 px
  • แบ่ง 72 / 14 / 14 ตามตัวคน (กราฟด้านล่าง)
  • รูปตัวอย่าง base + donor → fake พร้อมภาพความต่าง
  • กราฟจำนวน real/fake ต่อ split และการกระจายตามเชื้อชาติ เพศ อายุ

รูป fake ทุกรูปเริ่มจากรูปจริงสองรูป รูป base ให้ฉาก ผม และลำตัว ส่วนรูป donor ให้ใบหน้า โปรแกรม face swap จะเอาหน้าด้านในของ donor ไปแปะบน base pixel ที่เปลี่ยนมีแค่ประมาณ 11 % พื้นหลังจึงเหมือนรูปจริงทุกประการ

ขนาด

มี 69,831 รูป ขนาด 1024 × 1024 px เป็น real 38.6K และ fake 31.2K หลังทำความสะอาดเหลือ 69,476 รูป

Cleaning

ลบไฟล์ "real" 235 ไฟล์ที่จริง ๆ แล้วเป็นสำเนาของ fake ลบ fake 50 รูปที่ swap ไม่สำเร็จ และแก้ชื่อไฟล์ผิด 458 ไฟล์

เหตุผล: label ผิดจะสอนโมเดลผิด ๆ

Split ตามตัวคน

fake, base และ donor ของมันอยู่กองเดียวกันเสมอ ไม่มีคนไหนอยู่ทั้งใน train และ test

เหตุผล: ถ้าโมเดลเคยเห็นคนนั้นตอน train มันอาจจำหน้าคนแทนที่จะดูร่องรอยการ swap ซึ่งเท่ากับโกง

ทีม 4 คนต้องมีอย่างน้อย 3 วิธี ที่เหมาะกับปัญหาของข้อมูลพร้อมเหตุผล, เหตุผลของ augmentation, pipeline diagram ทีละขั้น และตัวอย่าง before / after ได้ 5 คะแนนเมื่อวิธีเหมาะกับปัญหาของข้อมูล (ถ้าเป็นวิธีทั่วไปได้ 3)

เราทำอย่างไร
  • 4 วิธี แต่ละวิธีแก้ปัญหาที่เจอใน HiDF จริง: P1 แก้ทางลัดเรื่องการบีบอัด, P2 ให้ทนรูปเสียหาย, P3 เพราะ swap เปลี่ยนแค่ 11 % ของรูป, P4 เพราะร่องรอยอยู่ในความถี่สูง
  • วัดผลว่าแก้ได้จริง: P1 ทำให้พื้นหลังเหลือ AUC 0.51, P3 ครอบคลุม swap 96 %, P2 ทดสอบด้วยการเปิด/ปิด
  • Pipeline diagram และ before/after อยู่ใน documents/figures/phase2/ (ดูตัวอย่าง P4 ในหัวข้อถัดไป)
P1

บีบอัดทุกรูปแบบเดียวกัน

บันทึกทุกรูปด้วยวิธีเดียวกัน (JPEG แล้วย่อเป็น 512 px)

ไฟล์ real กับ fake ถูกบันทึกมาต่างกัน แค่ดูขนาดไฟล์ก็แยกได้ (AUC 0.99) โดยไม่ต้องดูหน้าเลย P1 ลบเบาะแสนี้ออก

P2

Augmentation

สุ่ม crop, flip, เปลี่ยนสี, blur, JPEG, noise เฉพาะรูป train

ให้โมเดล deep learning รับมือกับรูปที่เสียหายได้

P3

หาตำแหน่งใบหน้า

ใช้ MediaPipe วาดขอบใบหน้า ครอบคลุม 96 % ของบริเวณที่ถูก swap

ใช้ crop หน้า และใช้คำนวณ feature แบบ classical

P4

Feature ที่ออกแบบเอง

ตัวเลข 247 ตัวต่อรูป: ความถี่ (FFT), noise, texture ผิว (LBP), สี และรอยต่อที่ขอบหน้า

เป็น input ของโมเดล classical

เจอ leakage ครั้งแรกและแก้แล้ว ก่อนทำ P1 โมเดลที่เห็นแค่พื้นหลัง (ปิดหน้าไว้) ยังแยก real กับ fake ได้ หลังทำ P1 คะแนนเหลือ 0.51 ซึ่งเท่ากับเดา เพราะเรื่องนี้เราจึงระวังเรื่อง leakage มาตั้งแต่ต้น

P4 อย่างละเอียด

Feature ที่ออกแบบเองทำอย่างไร

โมเดล classical ไม่ได้ดู pixel โดยตรง เราแปลงแต่ละรูปเป็นตัวเลข 247 ตัวที่วัดสิ่งที่คาดว่ารูป fake จะต่างจากรูปจริง แล้วค่อยให้โมเดลเรียนจากตัวเลขเหล่านี้ โค้ดอยู่ที่ src/features.py ใช้เวลาประมาณ 73 ms ต่อรูป

แนวคิดหลัก: หน้าที่ถูก swap เป็น pixel ที่โปรแกรมสร้างขึ้นใหม่ ผิวจึงเรียบกว่าและมี noise น้อยกว่าผิวจากกล้องจริง แต่ความต่างนี้เล็กมาก มองด้วยตาไม่เห็น เพราะถูกกลบด้วยเนื้อหาของรูป (รูปร่างหน้า สี แสงเงา) เราจึงต้องใช้ filter ลอกเนื้อหาออกก่อน ให้เหลือแต่รายละเอียดเล็ก ๆ

ขั้น 1

แบ่งบริเวณด้วย P3

ใช้ขอบหน้าจาก MediaPipe แบ่งรูปเป็น 4 ส่วน: หน้าด้านใน, แถบรอยต่อ (seam) ตามขอบหน้า, วงผิวรอบ ๆ หน้า และด้านนอก

จะได้เทียบหน้ากับส่วนอื่นของรูปเดียวกันได้

ขั้น 2

High-pass filter

ใช้ filter Laplacian และ SRM (filter มาตรฐานในงาน image forensics) ลบส่วนที่เปลี่ยนช้า ๆ ออก เหลือ residual คือ noise และรายละเอียดเล็ก ๆ

เป็นเทคนิค image processing ที่เรียนในวิชา

ขั้น 3

สรุปเป็นตัวเลข

คำนวณสถิติของแต่ละบริเวณ: ค่าเบี่ยงเบน (std), ค่าเฉลี่ยขนาด, skewness, kurtosis รวมถึง FFT, LBP, สี และความคมของขอบ (ดูตารางด้านล่าง)

ได้ตัวเลข 247 ตัวต่อรูป

ขั้น 4

ให้โมเดลเรียน

ลองโมเดล 4 แบบกับตัวเลขเหล่านี้: gradient boosting, logistic regression, SVM, random forest เลือกตัวที่ดีที่สุดจาก validation

Gradient boosting ชนะ (AUC 0.998)

สุดท้ายโมเดลใช้ feature ไหนจริง

เราวัดด้วย permutation importance: สุ่มสลับค่าของ feature กลุ่มหนึ่งแล้วดูว่า AUC ตกลงเท่าไร ถ้าตกมาก แปลว่ากลุ่มนั้นสำคัญ

  • LBP texture สำคัญที่สุด (AUC ตก 0.336) feature เดี่ยวที่สำคัญที่สุดคือสัดส่วนลวดลายผิวที่ "ไม่เป็นระเบียบ" ในหน้า
  • Noise หน้า vs นอกหน้า รองลงมา (ตก 0.056)
  • กลุ่มอื่นตกไม่ถึง 0.001 เพราะวัดสิ่งที่ซ้อนกับสองกลุ่มแรก

ทำไมต้องรู้ตำแหน่งหน้า (P3)

ถ้าใช้แต่ feature ทั้งรูป (FFT + noise ทั้งรูป ไม่ใช้ขอบหน้า) ได้ AUC แค่ 0.816 พอเพิ่ม feature ที่แยกหน้ากับส่วนอื่น AUC ขึ้นเป็น 0.998

สรุป: เบาะแสอยู่ที่ texture และ noise ของผิวหน้า นี่คือเหตุผลที่โมเดลนี้พังเมื่อรูปถูกเบลอหรือใส่ noise เพราะสองอย่างนี้ทำลายเบาะแสที่มันพึ่งพาโดยตรง (ดูหัวข้อ Robustness)

Zero-shot

ถามโมเดลใหญ่ ไม่ต้อง train

CLIP เทียบใบหน้ากับข้อความ "a real photo" กับ "a face-swapped photo" เราลอง SigLIP 2, PE และ Qwen2.5-VL (chat model ที่ถามให้ตอบ yes/no) ด้วย

ดูว่าไม่ train เลยจะได้แค่ไหน ดีสุดได้ accuracy 90.6 %

Classical

Feature ที่ออกแบบเอง + gradient boosting

เอาตัวเลข 247 ตัวจาก P4 เข้า gradient boosting (decision tree เล็ก ๆ หลายต้นช่วยกันโหวต)

เป็นแนวทาง image processing ตามที่เรียนในวิชา พบว่าผิวที่ถูก swap เรียบกว่าและมี noise น้อยกว่าผิวจริง

M1

EfficientNet-B4

network สำหรับรูปภาพแบบคลาสสิก train ทั้ง 17.6 ล้าน weights เป็นโมเดลเดียวกับที่ paper HiDF ใช้

baseline มาตรฐาน เอาไว้เทียบกับ paper

M2

GenD บน DINOv3

ใช้ DINOv3 ที่ pretrain มาแล้วแทบไม่แก้เลย train แค่ 101,000 weights (0.03 %)

ทดสอบว่าโมเดล pretrained ที่เก่งมาก ๆ ต้อง train เพิ่มแทบไม่ได้เลยหรือเปล่า

M3

DINOv3 + LoRA

DINOv3 ตัวเดียวกัน แต่ปรับด้วย LoRA: train 12.7 ล้าน weights (ประมาณ 4 %) ตามแนวของผู้ชนะ NTIRE 2026 challenge

สูตร state-of-the-art ในปัจจุบัน

12 runs

แต่ละโมเดล deep learning × 4 แบบ

Baseline (รูปเต็ม, 224 px, เปิด augmentation) แล้วเปลี่ยนทีละอย่าง: crop เฉพาะหน้า, ปิด augmentation, เพิ่ม resolution

เปลี่ยนทีละอย่างจะเห็นชัดว่าแต่ละตัวเลือกมีผลอย่างไร

Pipeline ของโมเดล deep learning

รูป HiDF → P1 (บีบอัดแบบเดียวกัน, 512 px) → [P3 crop หน้า: เฉพาะ adjustment] → [P2 augmentation: เฉพาะตอน train] → ย่อเป็น 224 px + normalise → model → score "fake" → เทียบ threshold (จาก val) → real / fake

อ่านตารางนี้อย่างไร

  • Zero-shot < classical < deep learning ช่องว่างพวกนี้ใหญ่กว่า confidence interval มาก จึงเป็นความต่างจริง
  • CI ของ deep learning ทั้งสามตัวซ้อนกัน บนรูปปกติ ยังบอกไม่ได้ว่าตัวไหนดีกว่า ทั้ง 12 runs อยู่ระหว่าง 99.6 % ถึง 99.8 %
  • ความผิดพลาดเกือบทั้งหมดเป็น fake ที่หลุด ไม่ใช่การแจ้งเตือนผิด เป็นผลจาก threshold ที่เลือกจาก validation

สิ่งที่ได้เรียนรู้จาก 4 แบบ

  • Crop เฉพาะหน้า: ได้ผลพอ ๆ กับรูปเต็ม เพราะโมเดลโฟกัสที่หน้าอยู่แล้ว
  • ปิด augmentation: รูปปกติได้ผลดีเท่าเดิม แต่รูปที่เสียหายแย่ลงมาก (ดูหัวข้อถัดไป)
  • เพิ่ม resolution: ไม่ได้ดีขึ้นชัดเจน แต่ช้ากว่ามาก M3 ที่ resolution สูงใช้ 13.5 ชั่วโมงต่อ epoch จึง train ได้แค่ 2 epochs

Robustness: ถ้ารูปเสียหายจะเป็นอย่างไร

รูปบน social media มักถูกบีบอัด ย่อ และเบลอ เราทำให้รูป test เสียหาย 9 แบบแล้วทดสอบใหม่ โดยไม่ train ใหม่

ทำไมเรื่องนี้สำคัญ โมเดล classical พึ่ง texture ละเอียดของผิว ซึ่ง blur และ noise ลบทิ้งไปหมด ส่วนโมเดล deep learning train ด้วย augmentation (ขั้น P2) จึงเรียนเบาะแสที่ทนต่อความเสียหายได้ ในความเสียหายทั้ง 9 แบบ M1 ยังแม่น ≥ 98.3 % M2 ≥ 96.6 % M3 ≥ 98.6 % นี่คือเหตุผลที่ชัดที่สุดที่ควรเลือก deep learning ในงานนี้

Analysis: ตัวอย่างสำเร็จ / ล้มเหลว และโมเดลดูตรงไหนของรูป

คะแนนสูงจะน่าเชื่อก็ต่อเมื่อโมเดลดูที่หน้าที่ถูก swap ไม่ใช่ดูอย่างอื่นที่ไม่เกี่ยว

Analysis (advantages + limitations)

ครบ
วิชาต้องการ

เทียบผลบน test ระหว่าง classical กับ deep learning: 3 ตัวอย่างที่ทำได้ดี (pros) และ 3 ตัวอย่างที่ล้มเหลว (cons & limitations) แต่ละตัวอย่างแสดง input + คำตอบของ classical + คำตอบของ DL

เราทำอย่างไร
  • เลือกตัวอย่างด้วยกฎ ไม่ได้เลือกเอง: สำเร็จ 3 = ที่ classical ผิดแต่ DL ทุกตัวถูก, ล้มเหลว 3 = ที่ทุกโมเดลผิด (รูปด้านล่าง)
  • อธิบายสาเหตุด้วย Grad-CAM และภาพความต่างจากรูป base
  • ข้อดี/ข้อจำกัดเพิ่ม: robustness (หัวข้อก่อนหน้า), fairness และข้อจำกัดท้ายหน้า

Grad-CAM คืออะไร เป็นเครื่องมือที่ช่วยให้เห็นว่าโมเดลใช้ส่วนไหนของรูปในการตัดสินใจ ทำงานแบบนี้:

  • ข้างในโมเดล รูปจะถูกแปลงเป็นตารางของ feature เล็ก ๆ หลายช่อง แต่ละช่องคือข้อมูลของพื้นที่หนึ่งในรูป (เช่น ตาซ้าย จมูก พื้นหลัง)
  • Grad-CAM คำนวณ gradient ว่าถ้า feature ในแต่ละช่องเปลี่ยนนิดหนึ่ง score "fake" จะเปลี่ยนมากแค่ไหน ช่องที่ทำให้ score เปลี่ยนมาก แปลว่าโมเดลใช้ช่องนั้นในการตัดสินใจมาก
  • เอาค่าความสำคัญของแต่ละช่องมาขยายให้เท่ารูปจริง แล้วระบายสีทับ: แดง = สำคัญมาก น้ำเงิน = แทบไม่สำคัญ

เราเทียบ heat map นี้กับ "เฉลย" ว่าบริเวณไหนถูก swap จริง (ได้จากความต่างระหว่างรูป fake กับรูป base) ถ้าสีแดงตกบนบริเวณ swap แปลว่าโมเดลดูถูกจุด Grad-CAM บอกแค่ "ดูตรงไหน" ไม่ได้บอกว่า "เห็นอะไร" ตรงนั้น

ปิดหน้า

เราปิดบริเวณใบหน้าเป็นสีเทาแล้วทดสอบทั้ง 12 runs ใหม่ AUC ตกเหลือ 0.51–0.53 (เท่ากับเดา) แสดงว่าโมเดลดูที่หน้า ไม่ได้ดูพื้นหลัง

ความร้อนอยู่บน swap

สัดส่วนความร้อนที่ตกในบริเวณ swap จริง: M1 47 %, M3 32 %, M2 24 % คิดเป็น 1.5–2.9 เท่าของการสุ่ม จุดที่ร้อนที่สุดตกบน swap 82–91 % ของรูป

ผิดตรงไหนบ่อย

ทุกโมเดลพลาดกับรูปที่ swap จางที่สุด โมเดล classical ยังทายรูปจริงที่ถูกรีทัชว่าเป็น fake ด้วย เพราะผิวที่เรียบจากการแต่งรูปดูเหมือนรอย swap

Fairness: ทำงานได้ดีเท่ากันกับทุกคนไหม

เราแยกผล test ตามเชื้อชาติ เพศ และอายุของคนในรูป โมเดล deep learning ผิดไม่เกิน 1.9 % ในทุกกลุ่ม ส่วนโมเดล classical ต่างกันระหว่างกลุ่มมากกว่า (fake หลุด 2–6 % แล้วแต่กลุ่ม)

มีรูปแบบหนึ่งที่เกิดกับทุกโมเดล: รูปคนเอเชียถูกแจ้งเตือนผิดมากที่สุด M2 และ M3 ยังปล่อย fake หลุดมากที่สุดในหน้าคนเอเชีย ส่วน classical และ M1 ปล่อยหลุดมากที่สุดในหน้าคนผิวดำ ขนาดกลุ่มอธิบายเรื่องนี้ไม่ได้ เพราะคนอินเดียเป็นกลุ่มที่เล็กที่สุด (1.8 % ของ train) แต่ไม่ได้แย่ที่สุด เรารายงานไว้เป็นข้อค้นพบ ยังไม่ได้แก้

ตรวจ leakage: คะแนนดีเกินจริงหรือเปล่า

99.8 % ดูน่าสงสัย เราจึงลิสต์ช่องทางรั่วที่เป็นไปได้ 16 ข้อแล้วตรวจทุกข้อ ด้านล่างคือ 5 การทดสอบเพิ่มเติมที่ทำหลัง Phase 5 ส่วนการตรวจก่อนหน้านี้ (split ตามตัวคน, แก้เรื่องชนิดไฟล์, ปิดหน้า, เลือก threshold จาก validation เท่านั้น) อยู่ใน LEAKAGE.md

ช่องทางรั่วที่สงสัยทดสอบอย่างไรผล
โมเดลดูประวัติการบีบอัดของหน้า ไม่ได้ดูการ swapT1เอารูปจริงใน test 2,000 รูปมาทำให้บริเวณหน้ามีประวัติการบันทึกไฟล์แบบเดียวกับ fake โดยไม่ swap ถ้าโมเดลทายว่า fake แปลว่ามันดูจากการบีบอัดไม่รั่ว โมเดล deep learning ทายว่า fake แค่ 0–0.1 % เท่ากับรูปที่ไม่ได้แตะ (แต่การเบลอหน้าเบา ๆ หลอกโมเดล classical ได้ 23 %)
fake มีตำแหน่งหรือขนาดหน้าต่างจาก real หรือคนทำ dataset เลือกรูป base แบบพิเศษT2train โมเดลด้วยตำแหน่งและขนาดหน้าเท่านั้น และเทียบรูปจริงที่ถูกใช้เป็น base กับรูปจริงที่ไม่เคยถูกใช้ไม่รั่ว ตำแหน่งและขนาดอย่างเดียวได้ AUC 0.54 (ใกล้เดา) รูปจริงทั้งสองแบบได้ score เท่ากัน
คนเดียวกันอยู่ทั้งใน train และ test แต่คนละ ID ทำให้โมเดลจำหน้าT3ใช้โมเดลจดจำใบหน้า (ArcFace) คัดเฉพาะรูป test ที่คนในรูปไม่มีหน้าคล้ายใน train เลยไม่รั่ว M3 แม่น 99.81 % กับคนที่ "ไม่เคยเห็น" เหล่านี้ เท่ากับส่วนที่เหลือ
รูปเดียวกัน (กลับด้าน crop หรือแต่ง) อยู่ทั้งใน train และ testT4เทียบรูป test ทุกรูปกับรูป train ทุกรูป ด้วย fingerprint ของรูปจาก DINOv3รั่วนิดหน่อย ไม่มีผล รูป test 42 รูป (0.44 %) ซ้ำกับรูปใน train ตัดออกแล้ว accuracy เปลี่ยนไม่ถึง 0.01 จุด
Bug ในโค้ดส่งคำตอบให้โมเดลT5train M2 โดยสุ่มสลับ label ของ train ถ้าไม่มีสัญญาณจริง pipeline ที่ไม่มี bug ต้องได้ประมาณ 0.5ไม่รั่ว AUC บน test 0.486

สรุป คะแนนที่เกือบสมบูรณ์แบบเป็นของจริงสำหรับ dataset นี้ และเป็นเรื่องปกติของโมเดลที่ train และ test บน fake ชนิดเดียวกัน dataset อื่นในสถานการณ์เดียวกันก็ได้ประมาณ 99 % เหมือนกัน

ตอบคำถามจากอาจารย์และเพื่อนในวันนำเสนอ และ review งานของกลุ่มอื่น

เราเตรียมอย่างไร
  • "ทำไมคะแนนสูงกว่า paper HiDF (0.70) มาก?" paper ไม่ได้ train บน HiDF เราทำ
  • "มี leakage หรือเปล่า?" ตรวจ 16 ข้อ (หัวข้อ Leakage)
  • "ใช้กับ deepfake แบบอื่นได้ไหม?" ยังไม่รู้ เป็นข้อจำกัดหลัก (ด้านล่าง)
  • "ทำไมไม่ใช้แค่ classical ที่ได้ 98 %?" พังเมื่อรูปเบลอหรือมี noise (หัวข้อ Robustness)

สิ่งที่ยังสรุปไม่ได้

  • fake ทุกรูปใน HiDF มาจากโปรแกรม face swap ตัวเดียว เราไม่รู้ว่าโมเดลจะทำได้แค่ไหนกับ deepfake จากโปรแกรมอื่น ต้องทดสอบกับ dataset อื่นถึงจะรู้
  • DINOv3 ถูก pretrain โดย Meta ด้วยรูปจำนวนมหาศาล ซึ่งอาจมีรูปจริงบางรูปซ้ำกับของเรา ข้อนี้ทดสอบไม่ได้
  • M3 ที่ resolution สูง train ได้แค่ 2 epochs เพราะช้ามาก
